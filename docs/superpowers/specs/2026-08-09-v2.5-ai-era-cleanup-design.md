# MacCleaner v2.5 — AI-Era Cleanup: /tmp build artifacts, simulators, AI-tool caches, tap publish

**Date:** 2026-08-09
**Status:** Approved (design validated in-session with Jordan; sequencing, /tmp approach, and simulator scope each confirmed explicitly)
**Prior art:** v2.1–v2.4 specs in this directory; the machine contract in `AGENTS.md`; the release procedure in `docs/RELEASING.md`

## Motivation

A real-world audit of Jordan's 460 GB Mac (99.9% full) found that MacCleaner's scan
reported 5.2 GB reclaimable while ~145 GB of developer debris sat invisible to it:

| Size | Location | Why MacCleaner missed it |
|---|---|---|
| 85 GB | `/private/tmp` — 720 per-session Xcode DerivedData dirs + iOS repo clones created by AI coding sessions | outside `$HOME`; the engine's hard home-only delete rule excludes it |
| 40 GB | `~/Library/Developer/CoreSimulator` — simulator devices + data | raw `rm` would corrupt simctl's device registry; needs cmd targets |
| 17.6 GB | `/Library/Developer` — simulator runtime images | outside `$HOME` + needs `simctl runtime` |
| ~7 GB | `~/.codex`, `~/.gemini`, `~/.cursor` | no targets exist for these tools |

The `/tmp` pattern — agent sessions creating a fresh DerivedData dir and repo clone
per session, never cleaned because macOS only reliably purges `/tmp` at boot — is an
AI-coding-era artifact that post-dates the original target list. v2.5 makes MacCleaner
the tool that catches it.

v2.5 also ships the CONFIG_PATH bundle fix (flagged in the v2.4 whole-branch review)
and, because releases are now notarized, ends with the Homebrew tap actually published.

## Non-goals

- No `simctl erase all` target (footgun for an active iOS developer; explicitly rejected)
- No general "clean anything outside $HOME" mechanism — the `/tmp` carve-out is
  deliberately narrow and non-configurable in scope
- No new app UI; the app picks the new targets up automatically through the existing
  JSON contract (superset rule: all changes additive)

## 1. `/tmp` build-artifact scanner (new subsystem)

### Approach: content heuristic (chosen over name patterns and over skipping /tmp)

A new `scan_tmp_artifacts(config)` modeled on `scan_projects()`:

- Walks **only the top level** of `/private/tmp` (no recursion into candidates; never
  descends into a classified dir, mirroring the projects scanner's never-descend rule).
- Classifies a directory as build junk by **content**, not name:
  - **DerivedData-style:** contains `Build/Intermediates.noindex`, or `*.xcactivitylog`
    under `Logs/Build/`, or the `info.plist` + `Build/` + `Index.noindex` DerivedData
    layout.
  - **Repo-clone-style:** contains `.git` AND a recognized manifest (`package.json`,
    `Cargo.toml`, `pyproject.toml`, `Package.swift`, `*.xcodeproj`, …the projects
    scanner's existing manifest list) AND at least one build-artifact dir from the
    projects scanner's artifact list (`build/`, `DerivedData/`, `.build/`, etc.).
- **Guards (all mandatory):**
  - Min age: dir mtime older than `tmp_min_age_days` (new config key, default `3`).
  - Never follows symlinks; a symlink at top level is never classified.
  - Skips dirs not owned by the current user.
  - Skips active-session dirs: any name matching `claude-*` (Claude Code scratchpads
    live under `/private/tmp/claude-<uid>/`), plus anything currently open — cheap
    proxy: skip dirs with mtime newer than the age gate, which the gate already does.
  - Skips the classic system entries (`com.apple.*`, sockets, files — only plain
    directories are ever candidates).

### Safety-rule carve-out

`delete_target()` keeps refusing everything outside `$HOME` **except** paths that
(a) resolve to a direct child of `/private/tmp` (or `/tmp`, which symlinks there —
resolve first, then check), and (b) were produced by `scan_tmp_artifacts()`
classification in the same run. Implementation: tmp targets carry an internal marker
(e.g. `t["tmp_scan"] = True`) set only by the scanner; `delete_target` checks the
marker AND re-verifies the resolved-parent rule at delete time. There is no config
key that widens this — it is not a general exception.

### Surfacing

- New category `tmp` ("Temp build artifacts"). Each classified dir becomes a target
  `tmp-<basename-slug>` with `safe=False` (**review-only** — a scheduled
  `clean --yes` can never touch these; explicit `--targets ... --yes` or interactive
  confirmation required, same consent rule as all review targets).
- Appears in `scan`, `clean`, `clean --dry-run`, and their `--json` outputs.
  JSON changes are additive (superset rule).
- **Static/dynamic split (important):** `get_targets()` stays static. `scan` and
  `clean` call `scan_tmp_artifacts()` at runtime (cheap — a top-level stat pass
  over ~/tmp entries) and merge the results into the working target list. The
  `categories` subcommand lists the `tmp` *category* (so `--category tmp` and
  category enable/disable work, and the completions' live category list picks it
  up) but not the per-dir dynamic IDs — mirroring how `projects` targets have
  never appeared in `categories`. Completions therefore complete `tmp` as a
  category; per-dir IDs are selected interactively via the TUI checklist or
  passed verbatim to `--targets` by agents reading `scan --json`.
- Because target IDs are per-dir and dynamic, `clean --targets tmp-all` is NOT added;
  the TUI checklist and `--category tmp` handle bulk selection (existing mechanics).

## 2. Simulator targets (existing cmd-target mechanism)

Four new targets in a new `simulators` category (kept separate from `xcode` so a
category disable is possible):

| ID | Mechanism | Safe? |
|---|---|---|
| `simulator-unavailable` | `xcrun simctl delete unavailable` | **safe** |
| `simulator-caches` | path target: `~/Library/Developer/CoreSimulator/Caches` | **safe** |
| `simulator-stale-devices` | devices whose `lastBootedAt` is older than `simulator_stale_days` (new config key, default `30`) — deleted individually via `xcrun simctl delete <udid>`; devices that have never been booted count as stale only if created older than the gate (fall back to the device dir's mtime when `lastBootedAt` is absent) | review |
| `simulator-unused-runtimes` | runtime images with zero remaining devices, via `xcrun simctl runtime delete <id>` | review |

- Estimation via `estimate_cmd` parsers: `simctl list devices -j` (device data dirs
  sized with the existing du machinery), `simctl runtime list -j` (sizes reported
  directly). A missing `xcrun`/`simctl` (no Xcode) degrades exactly like a missing
  `docker`: target reports 0 and is skipped — doctor already reports tool presence.
- Ordering note: `simulator-stale-devices` runs before `simulator-unused-runtimes`
  when both are selected, but orphaned runtimes are only offered on the NEXT scan,
  not the same run — the code conservatively counts every device's runtime as
  "used" while building this scan's target list (the stale device hasn't actually
  been deleted yet at that point), so a runtime it would orphan still looks in-use
  until the following scan re-enumerates devices.
- Booted devices are never stale (a booted device has a current `lastBootedAt`).

## 3. AI-tool cache targets (extend the `ai` category)

- Safe path targets for cache subdirectories of `~/.codex`, `~/.gemini`, `~/.cursor`
  — the exact subpaths are determined **empirically during implementation** by
  inspecting real layouts on this machine (e.g. cache/, tmp/, logs/ subdirs). Never
  the whole dotdir: `auth.json`, API keys, and user config live there.
- One review target for aged session transcripts (age-gated by the existing
  project-age config pattern) if inspection shows transcripts are the bulk — if a
  tool's layout makes transcripts inseparable from state, skip that tool rather
  than risk it.
- Follows the existing add() idiom in `get_targets()`; IDs like `codex-cache`,
  `gemini-cache`, `cursor-cache` (stable kebab-case).

## 4. CONFIG_PATH bundle fix

`CONFIG_PATH` currently resolves beside `cleaner.py` unconditionally — inside a
signed `.app` bundle for a cask/bundled install, where writing corrupts the
signature (and fails on a read-only mount). Fix: route it through the same
bundle-aware `_resolve_state_path` logic used by `report.log`/`snapshots.log`/
`alerts.json` (beside `cleaner.py`, falling back to
`~/Library/Application Support/MacCleaner/` when unwritable OR inside a `.app`).
`MACCLEANER_CONFIG` env override still always wins (tests depend on it).
Migration: if a legacy beside-the-script `config.json` exists and is readable, it
keeps being read (existing installs see no change — `~/mac-cleaner` is writable);
the Application Support fallback only engages for bundle-resident engines.

## Testing

- **Classifier fixtures:** positive (DerivedData layout, repo-clone layout),
  negative (plain dir, named-like-DerivedData-but-empty, too-young dir, symlink,
  other-owner dir simulated via mock), all under a `MACCLEANER_TMP_ROOT`-style env
  override so tests never touch the real `/private/tmp` (mirrors
  `MACCLEANER_LAUNCH_AGENTS_DIR`).
- **Carve-out tests:** `delete_target` still refuses arbitrary non-home paths;
  refuses a `/private/tmp` child WITHOUT the scanner marker; accepts with marker;
  refuses marker + non-tmp path (belt and braces).
- **simctl estimators:** canned `simctl list -j` / `runtime list -j` JSON through
  the parsers; missing-simctl degradation.
- **CONFIG_PATH:** bundle-resident engine writes config to Application Support;
  repo/installed engine unchanged; env override wins.
- **Contract:** every new key additive; `AGENTS.md` examples updated; completions
  cross-ref suite passes (51+ assertions).
- CI unchanged (unit suite + completions suite + smoke tests already wired).

## Rollout note for the app

No Swift changes required: new categories/targets flow through `ScanReport`
decoding as data. The Dashboard groups by category name, so `tmp` and `simulators`
appear automatically. (Verified assumption from v2.1: adding categories in the
engine surfaced in the app without code changes.)
